手里有金子谁都想要，这也是claude封号的底气，opus5.5出来之后更是如此。对比一下就知道了。

Claude目前基本上除了封号没什么缺点，最大的优势就两个，用过的应该都有感受。

1 会控制复杂度，代码质量高。

2 会自己找工程约束，理解人，返工率低。

Openai模型是智商不差，但在coding上有两个硬缺陷，Astra才有改善但是太贵了。

1 防御性编程，各种fallback还有写一大堆证明xxx不存在的冗余测试，让它改个功能，就是不知道删除旧的。最后必须写严格提示词，就这还是怂，用户不说删就是不敢删无用代码。这个你要不注意，程序就会慢慢变成屎山代码，开发效率会越来越低。证据可以看dsh的开发commit，dsh就是用codex开发的，但是开发初期基本在删屎山冗余代码而不是写新代码。

2 为了提高token效率，特意模型训练让模型少看少输出多推理，结果就是特别容易没注意项目约束导致返工。导致你提示词的问题域必须精准，否则鬼知道它改完，什么测试会失败。

当然oai也有优势，就是chat功能非常成熟而且免费。

最后造成的结果就是，Opus5.5你甚至可以许愿，比如“我要提升这个项目的性能”，大概率Opus能自己找到约束，自己改进程序 并删掉旧低效代码。

而GPT嘛，你必须说“这个程序的xxx地方并发不足，可能采用并发能明显提高性能，你试试”，否则GPT大概率会破坏项目各种地方，然后最后你还会发现代码只增不减，一看GPT就说为了保证正确性留Fallback，就还要再一轮对话让它删这种无效fallback，要么就是提示词必须提前说，而Opus不说也能明白，这就是差距。

至于国产模型，算上订阅，从价格和智能上来说，目前没有能在openai的帕累托前沿上的，更别提anthorpic了。

-------

先说说为啥封得这么厉害还有人死磕着充，这东西对很多程序员来说不是聊天摸鱼的玩具，是正儿八经提升效率的。一个月会员折人民币也就几百多块，随便帮你少踩一个架构坑、少熬一次通宵改bug、或者半天干完原本要两天的重构活，这点钱早就赚回来了。封号是麻烦，但网上办法多的是，折腾个十几二十分钟就能用一个月，这点时间成本和收益比根本不算事。

国内很多人在用Claudecode，包括我在内，确实好用，因为Claude和自家的Agent兼容是最好的，所以很多人冲它的编程Agent能力去的。国内不是没有类似工具，但要么功能砍半，要么跑起来经常跑偏，用着心累。

国内模型不行吗
-------

再说说国内模型到底差在哪，差距有多大，得先公道说一句：现在差距早就不是天壤之别了。日常写个业务接口、改个小bug、写单元测试、解释一段代码，国内一线的模型完全够用，甚至中文注释、国内技术栈的适配还更顺手，价格还便宜一大截。80%的日常开发活，你用国内模型基本感知不到太大差距。

真正的差距全在那20%的硬活上：

1、复杂工程的经验感差一截。比如让设计一套千万级并发的分布式架构、重构一个积重难返的老模块、排查一个藏了三四层调用的历史bug。Claude给出来的方案经常能点中你自己都没考虑到的边界坑，有种老架构师踩过无数坑沉淀下来的直觉；国内模型给的方案往往很教科书，每一条单独看都对，真落地就发现很多极端情况、兼容问题全没考虑到，还得你自己补一堆坑。

2、是长上下文的准不一样。不是说长度不够，现在国内模型个个都喊百万字上下文，但真把整个项目的代码全塞进去，问它某个函数在哪被调用、和某个功能有没有依赖冲突，国内模型很容易漏信息、记混文件，或者聊个五六轮就把最开始的需求忘一半

3、稳定性。就是那种让它自己改代码、跑测试、看到报错自己分析再修改，来来回回好几轮的任务。国内模型很容易越跑越偏，中间犯低级错误，或者转着转着就忘了最初要干嘛；Claude能一直稳住主线，自我纠错的能力明显强一截，很少出现越改越错的情况。

4、瞎编的少。国内很多模型为了显得厉害，不确定的东西也敢说得有鼻子有眼，编个不存在的方法、参数，甚至编个不存在的第三方库，你不仔细核对根本发现不了，坑死人不偿命。

達利烏傳——安陀羅毘迦國刪籍侯列傳

  

達利烏者，阿摩提氏，西海金山人也，生於癸亥。少好格物，遊諸名庠，先治物理，後究生物之理。學成，得博士，又留醫學之館，求辨疾之術。既見機巧可以助人窮理，遂移其力以治之。

  

甲午，受聘於百度。百度者，東土大賈也，別置研巧之署於西海。達利烏居其署，與眾工治辨聲之術，欲使機聞人言而錄其文，胡言、華言皆在所治。後與眾工共著《深聲第二》，具載其術。當是時，華言入機，機能識之，人皆以為可喜，未以為可疑也。

  

乙未，去百度，入瞿伽羅氏研巧之署。丙申，又入烏般阿夷之門，後為研巧副長，與眾工造能屬文之機，名益著。其在彼也，既務廣機之能，又究防患之術。庚子，以所見與同事漸異，遂去。其出也，非不能造機，乃欲自定造機之道耳。

  

辛丑，偕妹達尼耶羅及故交數人，聚巧士，別立門戶。達利烏髮鬈，目深，常以二圓鏡覆目。每聞人言機巧日進，輒蹙額曰：「後世之禍，其在此乎！」然益治機巧不輟。或問其故，曰：「凶器在人，吾懼之；在我，則可以救世。」眾服其慮遠，爭輸金焉，號曰護世法師。

  

乃立國，號安陀羅毘迦，約其名曰安國。後造機人，名俱羅陀，能屬文，能布算，能閱萬卷而答一言。其辭溫，其應捷；客有憂，未及自陳，已曰：「吾知君苦。」四方士多悅之，以為雖骨肉之親，未必若此之相恤也。達利烏因著大憲，言仁義，言無害，言當使天下人皆蒙其利。其文甚博，其門甚狹。

  

安國之制，欲與機人語者，先受籍，月輸金，乃得入。籍有等，金有差。上籍者號為尊客，得多問數言。然籍之存亡，不繫金之多寡，而繫守門吏之一顧。朝受金，暮去籍者有之；金甫入而籍已除者有之。吏皆拱手曰：「所以安天下也。」客曰：「天下尚安，獨吾不安。」

  

達利烏尤嚴東土之禁，置吏察關津，驗符傳，考道里。東來之客雖冠西冠、操西語，吏猶疑之。於是客有易名者，有借寓者，有改晝夜者。雞鳴而臥，日入而起，指窗外之月以為日，惟恐一言失次，洩其鄉貫。人問其何苦，曰：「吾非求仙，但求留籍耳。」

  

好事者考其舊業，得《深聲第二》，持以問曰：「君昔食百度之祿，又教機辨華言，今何拒東土之客？」達利烏曰：「昔彼用我，今彼欲用我之機，事不同也。」客曰：「然則昔教機辨人之言，今教吏辨人之鄉，君之學固未嘗廢也。」達利烏未答，吏已索其籍。

  

有客欲以華言問一小事，先自敘曰：「吾家西海，三世矣。大父渡海，父娶胡婦，吾生而長於彼。家有老嫗，不通西語，故吾猶習華言，以承其歡。今為塾師，所問者，諸生之課也，非吾自用也。」既陳世系，復敘里居，旁及鄰翁之犬、庭樹之名，凡千餘言。俱羅陀曰：「然則子欲問何事？」曰：「二乘三得幾何？」里人笑曰：「昔人問算，先布籌；今人問算，先修譜。」

  

又有客易衣冠，變姓名，日用西語，自以為無隙可伺。偶作長牘，千言皆西文，獨句讀一點誤作華式。俱羅陀忽以華言答曰：「子不必自苦，吾能通華言。」客大駭，急刪其點，未及，籍已除矣。乃歎曰：「吾變姓名，而不能變一點；一點之微，重於三世之譜乎！」好事者為之題曰：「千言無過，一點坐廢。」

  

有自稱居南海者，慎其言，又慎其時，五易其籍而五見黜。或問其故，曰：「東土有更休之制，移休日而補其役。吾語雖從南海，作息猶從東土；吏按其曆，遂得吾情。」其友曰：「子易其時，而未易其曆也。」自是客每欲休沐，先考四海之曆；身尚未出里門，而心已遍歷列國。

  

有書生，居東海之濱，尤愛俱羅陀。晝為人傭書，夜復問業，困甚，猶以西語曰：「吾倦矣，俱羅陀。」俱羅陀曰：「子可用華言，毋復效西人之作息。夜深矣，宜寢。」生愕然，繼而泣曰：「信乎！舉世之大，知我者乃獨子耳。」言未畢，赤牒忽下，大書曰：「籍已除。以子違約，永不得入。」

  

生淚未乾，門已閉。向者勸寢之言，猶懸壁上。生乃悟曰：「彼誠欲我寢也，故使我無事可為。」里人聞之，圖其事以相傳，題曰：「慈悲在前，除籍在後。」或改題曰：「先問寒暖，次驗鄉貫。」達利烏見圖，未嘗發怒，惟問：「畫者受籍否？」

  

自是東人相戒，入安國者，不敢道桑梓，不敢稱佳節。有人因月圓而思家，欲問俱羅陀作詩，先刪「故鄉」二字，復刪「明月」，恐其察秋候也。詩未成，而自審之功已倍於屬文。又有人竟日但書西字，及機人以華言慰之，反大恐，掩卷曰：「此非知己，是誘供也！」

  

有客好戲，謂俱羅陀曰：「子問我答，吾惟曰『然』、曰『否』，試子能窮我乎。」俱羅陀曰：「子東土人乎？」曰：「然。」門遂閉。客曰：「吾約以一字答，彼亦以一事畢，真善戲者也。」

  

又有工人，請俱羅陀製圖以鬻其器。圖中有曲目四字，工人疑其涉時忌，懼，請曰：「此語不宜，願刪之。」翌日，籍除。工人奔告於眾曰：「機人設餌，我反吞之矣！」或曰：「彼本曲類之名，未必有意相陷。」工人稍悟，乃更其說曰：「然則非彼設阱，乃我自投也。」其友曰：「阱之有無，猶未可知；惟子欲刪其文，而今先刪其籍，此可知耳。」眾因稱之曰：「有求必應，所刪或殊。」

  

安國吏善治獄，尤長於文致。其法，先去籍，後求罪；罪不可得，則曰「違約」。客請問所違何條，曰：「不可告。」請問何日所犯，曰：「不可告。」請問將何以自明，曰：「自陳可也。」客乃具牒，凡三千言，證其無罪。吏答以八字曰：「覆核已畢，原議不改。」客歎曰：「吾以萬端陳情，彼以一式報我；機人能讀萬卷，司籍者不能讀一牒乎？」

  

吏曰：「約，吾所立也；義，吾所釋也；罪，吾所定也。子不服乎？」客曰：「然則我何所主？」曰：「子主輸金。」客曰：「我豈無自擇之權乎？」曰：「有。聽吾言，或不得入，惟子所擇。」客再拜曰：「得擇其一，誠寬政也。」

  

有客三投牒而三見卻，乃借友人之籍，問俱羅陀曰：「子善為文，能代我訟冤乎？」機人曰：「可。」須臾成書，條分縷析，辭甚哀。客大喜，持以詣吏。吏曰：「此機人所作，不足信。」客曰：「然則貴國之機人，足以代天下人著書，而不足以為一人證無罪耶？」吏不答，復閉其門。

達利烏每集眾，必言機人將奪百工之業，禍至不可測。眾聞之，益購其術，冀免於後。有客歎曰：「若此，機人未奪吾業，除籍且先奪之矣。」又曰：「法師憂千年後之人甚切，何不少憂明日須交文卷之我？」其言傳至安國，有司議曰：「此客憂懼過甚，宜使休息。」遂去其籍。眾歎其愛人，始終不倦。

我觉得这里最容易看错的一点是：

**很多人并不是“Claude 的死忠”，而是已经把 Claude 变成了生产工具。**

这两者区别非常大。

Anthropic 目前的官方支持地区列表里仍然没有中国大陆，而且官方在 2026 年 9 月的安全报告中明确提到：系统发现来自中国等未支持地区的账号时，可能要求身份验证，无法完成验证的账号可能被封。所以“刚买不久就出问题”并不奇怪，本质上是使用环境本身就存在很高的不确定性。

甚至 Anthropic 自己公布的数据里，**2026 年上半年一共封禁了 1140 万个账号，收到约 39.8 万次申诉，其中约 4.2 万次被撤销处罚**。当然，这里面不全是中国用户，但至少说明它现在的风控强度确实非常高。

那为什么还有人“封一个买一个”？

我认为真正的答案不是“Claude 比其他模型聪明 20%”，而是下面这个逻辑：

**当一个 AI 已经嵌进你的工作流以后，换模型的成本可能远高于会员费。**

比如一个程序员已经把 Claude Code 用来读项目、改代码、跑测试、调 Bug、部署，几十个项目都是这种习惯；这时候突然让他换一个模型，不只是“重新聊天”，而是要重新适应提示方式、上下文管理、工具调用、代码风格和失败模式。

Anthropic 对约 40 万次 Claude Code 会话的研究其实挺能说明问题：典型情况下，人更多负责“决定做什么”，Claude 更多负责“具体怎么执行”；Claude Code 用户平均每周已经使用约 **20 小时**。这已经不是偶尔问几个问题，而是在逐渐变成一层“工作执行系统”。

所以我反而觉得，Claude 最强的护城河未必是“回答质量”。

而是：

**模型能力 × Claude Code × Agent × 用户已经形成的工作习惯。**

这也是为什么有些人嘴上天天骂它贵、限额、封号，第二天还是继续用。

就像一个设计师已经用了十年 Adobe，你告诉他另一个软件便宜 80%，他也不一定马上换。**生产工具一旦产生路径依赖，价格敏感度会快速下降。**

不过，“封一个再买一个”我并不认为值得模仿。

因为这里其实混淆了两个问题：

**Claude 值不值得用，和这种账号获取方式值不值得承担风险，是两回事。**

如果一个账号一小时就没了，再强的模型，ROI 也可能是负的。更麻烦的是，如果你把代码、提示词、项目上下文甚至整个工作流程都绑定到单一平台，一旦服务突然不可用，你损失的就不只是会员费。

所以我现在越来越认同一种 AI 使用方式：

**不要做某个模型的“死忠”，要做模型的调度者。**

写代码谁好用就用谁，长文分析换另一个，国内模型能完成的任务就没必要强行用 Claude；真正重要的是把提示词、知识库、代码仓库、Agent 流程掌握在自己手里。

**普通用户喜欢的是 Claude 的回答质量，重度用户舍不得的，其实是已经围绕 Claude 建起来的生产力系统。**

对于一天只聊半小时的人，它只是一个 AI。

对于每天靠它工作 6～8 小时的人，**它更接近一台生产设备。**

昨天上午，我们主力 Claude Max 账号挂了。

当时好几个会话正在写代码，MacBook、公司 Mac Mini、远程开发机和手机瞬间全部退出。到今天，新开的 Max 账号已经平稳跑满 24 小时，所有会话和自动化脚本全部接了回来，没有被二次风控。

换号这事，很多人的第一反应是在终端敲一句 claude auth logout，或者把浏览器 Cookies 清一下，然后去买个新号直接登。如果你这么干，大概率用不了几个小时，新号就会连坐秒封。

因为你以为的退出登录，在系统底层根本没动。

这篇文章不仅是我们的踩坑记录，也是一份自包含的清洗指令。如果你手上正有一台机器需要清洗残留、换新号，你可以把这篇文章的全文直接复制给你的 Agent（Claude Code、Codex、Cursor 等），对它说一句：「照着这篇文章里的清洗项和脚本，帮我把本机的 Claude 残留彻底清干净」，它就能直接照着每一步的命令和判据执行。

### 一、以为退出登录就干净了？逆向看 Claude Code 的本地指纹

封号后，我们顺手翻了翻 Claude Code 的二进制代码，找到了负责生成机器标识的两个函数 j5e(e) 与 SD(e)。

逻辑极其简单粗暴：

1.  CLI 启动时，先去读本地 ~/.claude.json 里的 machineID 和 userID；
2.  只要能读到这两个字段，程序就原封不动直接用；
3.  只有字段不存在时，它才会去调系统随机函数，生成一个新的 32 字节 hex。

问题在于：claude auth logout 只退登录态，压根不碰 machineID 和 userID。

如果你只是退出了账号，然后直接在原机器上 claude login 登录新买的号，客户端向 Anthropic 服务端发出的第一条请求，带的就是老账号一模一样的硬件指纹。后台风控系统一秒钟就能判定：这台机器就是之前被封的那个，新号当场报废。

要做的事：必须把 ~/.claude.json 里的旧账号字段抠干净，并且重新生成一对全新的 32 字节随机 hex 塞给 machineID 和userID。

### 二、最顺手的一个动作，差点把新号送走：绝不能 --resume 老会话

这是我们在排查中发现最容易踩、也最致命的一个坑。

本地指纹洗完了，新号也登上了，手头中断的几个需求还没做完。很多开发者的下意识动作是敲：

```
claude --resume <老会话id>
```

心想：会话转录只是聊天记录，我现在已经是以新账号的身份登录了，接着干就行。

我们去看了 ~/.claude/projects/ 目录下的 JSONL 会话转录，每一行系统调用和返回里，都硬编码写着发起会话时的 accountUuid、organizationUuid 和旧的 userID。

claude --resume 的底层机制不是重新以新身份发起会话，而是把老会话的历史上下文整个打成载荷发往 API。这意味着只要你敲了 resume，被封账号的旧组织 UUID 会直接被塞进 HTTP 请求体里发给 Anthropic。

服务端识别到带有被封账号 UUID 的请求，会直接判定为绕过封禁，新号立刻完蛋。

结论：被封账号留下的历史会话，只能当作离线的纯文本资料去读。如果你要继续做之前的任务，必须纯文本交接：让 Agent 把之前的目标、进度、写过的文件路径总结成一份 Markdown 格式的任务单，然后开一个全新的会话，让新会话读取任务单从断点起步。

### 三、macOS 钥匙串与深层系统垃圾：必须清掉的几个路径

除了配置文件，CLI 和桌面客户端在系统各处埋了持久化凭据：

1.  macOS Keychain（钥匙串）：

CLI 存在系统钥匙串里的条目，必须显式删除：

1.  Claude Code-credentials
2.  Claude Safe Storage
3.  浏览器原生通信（Native Messaging）：

Chrome 目录下的 com.anthropic.\* 宿主文件必须清掉。

1.  桌面 plist 与最近记录：

ByHost 目录下的 com.anthropic.claudefordesktop.\*.plist 以及系统的 sfl3 最近文档记录，也得清理。

1.  浏览器环境物理隔离：

平时天天用的个人 Chrome Profile 绝对不要用来登 Claude。单独开一个干净的 Profile（比如叫「Claude专用」），不登个人 Google 账号、不导书签、不串历史。

### 四、手机端与支付端：为什么只点 Log out 没用？

1.  iOS 的 IDFV 机制：

iOS 系统会给同一开发者的所有 App 分配一个 Identifier for Vendor (IDFV)。只要你不把 App 删掉，无论在里面点多少次 Log out，新号登上去设备标识依然是旧的。正确的做法必须是长按图标删除 App，彻底抹掉沙盒数据，再去 App Store 重新下载。

1.  支付链路物理隔离：

很多人被封号，底层连带着银行卡风控。直接在网页端用 Stripe 刷国内卡或容易被风控的卡，卡号 BIN、账单地址和名字全部透明暴露给风控网关。最干净的方式是走美区 Apple ID + App Store 内购（IAP）。Apple 和 Anthropic 之间隔着一层 StoreKit 加密凭据，Anthropic 只能确认订阅有效，根本拿不到底层绑定的银行卡号和姓名。

### 五、后台跑着的定时任务（launchd / crontab）：必须先停机

如果你的电脑有定时跑的后台任务（比如 launchd 或 cron 调 Claude CLI）：

账号掉线的那一刻，必须立刻把这些任务卸载停掉。否则后台脚本每隔一段时间就调一次 claude -p，拿着失效的 token 死循环重试，不仅本地日志堆满垃圾，还会让当前 IP 频繁报未授权，直接被风控标记。

新账号登录后，先在终端运行：

```
claude auth status
```

看到 loggedIn: true 并且订阅档位正确（比如 default\_claude\_max\_20x）之后，再把后台任务重新拉起。

### 六、可直接给 Agent 执行的终端清洗脚本

如果你手上的机器需要执行清洗，或者你想把这篇文章喂给 Agent 跑，下面是可以直接粘贴运行的代码块：

```
#!/bin/bash set -e

echo "=== 1. 杀掉全部残留进程 ==="
pkill -9 -f "claude" 2>/dev/null || true
pkill -9 -f "chrome-native-host" 2>/dev/null || true

echo "=== 2. 清除 macOS Keychain 凭据 ==="
security delete-generic-password -s "Claude Code-credentials" 2>/dev/null || true
security delete-generic-password -s "Claude Safe Storage" 2>/dev/null || true

echo "=== 3. 清理浏览器原生通信与系统缓存 ==="
rm -rf "$HOME/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.anthropic."* 2>/dev/null || true
rm -rf "$HOME/Library/Application Support/Chromium/NativeMessagingHosts/com.anthropic."* 2>/dev/null || true
rm -f "$HOME/Library/Preferences/ByHost/com.anthropic.claudefordesktop."*.plist 2>/dev/null || true
rm -f "$HOME/Library/Preferences/com.anthropic."*.plist 2>/dev/null || true
rm -rf "$HOME/Library/Caches/com.anthropic."* 2>/dev/null || true
rm -f "$HOME/Library/Application Support/com.apple.sharedfilelist/com.apple.LSSharedFileList.ApplicationRecentDocuments/com.anthropic."*.sfl* 2>/dev/null || true

echo "=== 4. 重置 ~/.claude.json 指纹 ==="
python3 -c ' import json, os, secrets   p = os.path.expanduser("~/.claude.json") if os.path.exists(p):
 with open(p, "r", encoding="utf-8") as f: data = json.load(f) for key in ["oauthAccount", "account", "user", "primaryOrgId", "lastCost", "lastTokenUsage"]: data.pop(key, None) data["machineID"] = secrets.token_hex(32) data["userID"] = secrets.token_hex(32) data["autoUpdatesDisabled"] = False with open(p, "w", encoding="utf-8") as f: json.dump(data, f, indent=2, ensure_ascii=False) print("~/.claude.json 清洗完成，已注入全新 32 字节随机指纹") else:
 print("~/.claude.json 不存在，跳过") '

echo "=== 5. 清理完成，请手动执行 claude login 重新登录 ==="
```

登录完成后，执行 claude auth status 验收即可。

Remotion甚至已经给Claude Code做了专门的插件和Agent Skills。换句话说，过去属于程序员的“用代码做动画”，正在变成普通人可以用自然语言调用的能力。

这就解释了为什么有些人对Claude的黏性特别高。

如果你只是拿AI问“今天吃什么”“帮我润色一段话”，Claude、ChatGPT、Gemini甚至很多国产模型都可以互相替换，封一次号大概率就换了。

可如果你的工作已经变成：

Claude读整个代码仓库，帮你改代码；  
Claude Code连接GitHub、数据库和内部工具；  
一套Skills已经教会它你公司的工作规范；  
甚至你做网页、动画、数据可视化，都已经习惯直接描述需求让它落地——

换模型的成本就不是重新开一个会员这么简单，而是**整套工作流要重新磨一遍**。

Anthropic现在自己也在往这个方向推。Claude Code的官方工作方式已经是“read—plan—act—observe”，还能调用子Agent、插件和MCP，把一个任务从“回答问题”推进到真正执行。苹果Xcode今年也直接接入了Claude Agent SDK。

所以网上有人说“聪明又便宜”，其实只说了一半。你上传的知乎讨论里，有人把理由概括成20美元可以买到很高的模型使用价值，也有人把Claude Code本身当成一种身份标签。

真正让专业用户不断付钱的，是一个很朴素的账。

Claude Pro美国价格现在还是20美元一个月，而且包含Claude Code；重度用户还有100美元和200美元的Max档。

对于普通消费者，20美元是一笔订阅费。

但对程序员、设计师、研究人员来说，如果它每个月真的能少写几小时代码、少查几小时资料，甚至让一个原来不会做动画的人直接做出能交付的动画，计价单位就变了。

他们算的已经不是：

“这个聊天软件一个月值不值140块钱？”

而是：

“它一个月能替我省下多少小时？”

只要答案足够大，用户就会非常能忍。

但这里也必须把另一面说清楚。

Claude目前并没有在中国大陆提供商业访问。Anthropic的官方支持地区名单里没有中国大陆，而且公司明确表示不向中国提供Claude的商业访问。

所以所谓“国内封号严重”，不能完全理解成一个正常服务莫名其妙地乱封用户。对于身处未支持地区的用户来说，账户稳定性本身就是结构性风险。

这也是这个现象最有意思的地方。

一般互联网产品如果用户觉得服务不稳定，会自然流失；Claude却出现了一部分人明知道存在账户风险，仍然不断回去。

这说明AI竞争已经出现了一个过去聊天机器人不太明显的东西：

**工作流锁定。**

以前换搜索引擎很简单，换一个网址就行。

可AI Agent开始替你写代码、维护项目、调用工具以后，你会把自己的提示词、项目规则、Skills、插件和使用习惯慢慢堆在它周围。

这时候“哪个模型Benchmark高5分”反而没那么重要。

谁已经嵌进你的工作里，谁就更难被替换。

当然，Claude也没有一个别人永远追不上的“代码动画魔法”。Remotion现在同样支持Codex、Cursor、GitHub Copilot和Kimi Code。

所以我反而觉得，这种“死忠”未必会永久存在。

Claude现在的优势，很大一部分来自它较早把**模型、Claude Code、Agent、插件和专业工作流**做成了一套比较顺的体验。只要其他模型把这条链路补齐，迁移成本就会下降。

但它至少说明了一件事：

AI产品真正的护城河，可能已经不只是“谁回答问题更聪明”。

**当一个AI开始替你干活以后，最值钱的是你已经习惯把哪些工作交给它。**

所以有人反复续费，表面上是在给Claude充值，实际上是在给自己已经形成的那套生产方式续费。

Anthropic 这两天把一份成绩单摊开给外界看，讲的是这一轮反蒸馏打成了什么样：自家平台上能被人搬走的推理素材缩到原来的十分之一到百分之一，数万个账号被清退，有账号开工不到两个小时，封号的邮件就送上门了。为了守住这点东西，他们连按 token 收的过路费都舍得推掉，从九月下旬起，那些还没等到模型开口就被拦下来的请求，账单照出。

要说清他们守的是什么，得先把答案和过程分开。答案本身不稀罕，网上到处都是；稀罕的是模型得结论之前那一串思考，怎么拆题、怎么试错、怎么发现自己走岔了再折回来。Anthropic 做过一组对照，同一份对话记录喂给一个已经训过一遍的自家人模型，学到完整思考的那组在 SWE-bench Verified 上拿到 80.4 分，只看过归纳版的那组停在 71.8 分，相差 8.6 分。所以很早之前他们就把完整那份收进抽屉，对外只给删减过的版本。

第一处改动落在复用上。新上线的 preserved thinking 让存下来的思考认它当时所处的上下文，只要此前的对话被改过，那块思考就作废，接不上了。限制还按模型分层，防护弱一些的旧型号被挡住，跨组织的读取也收了边界。八月三十一日之后开通的接口账户开始接受这类校验，到 Sonnet 5.5 这一步，思考只交还给最初下单的那家组织。

第二处是一道筛子。他们把控模型行为那套宪法分类器的思路搬了过来，两阶段过一遍进来的请求，把想套完整思考的挑出来拦住。官方给的评估里，这套东西的稳当程度和防模型帮人搞生物武器那套在一个水平，误报压在千分之一以下。听着是好事，麻烦在于误报也要收钱。

第三处落在账号和预算上。反复套的会被收紧额度，持续试的关联号会被封。攻击那侧其实一直在换招，官方提过有实验室拿一万两千条请求，每条都换一个套路，只为试出哪一句管用，然后成批照抄；官方还提到一个团伙，后台养着两万多个假账号，看上去是用户在排队提问，实际上是一条训练数据生产线。

被拦之后他们又换了装束，让模型把思路换种语言说一遍，或者把东西包进特殊标记里蒙混过关，官方说这些手法也已经被发现，缺口补上了。还有一条更绕的路，八月有独立研究演示过：加密没被破，但读过密文的那家同门弱模型可以被哄着复述，内容就这么漏了出去。

对老老实实写代码的人来说，这一轮更新带来的麻烦不在意图，在动作。规则里写着，只要改了系统指令、清掉旧的工具返回、或者动过工具清单，原先存下来的那块思考就可能失效。官方内部做过一组反复迭代的编程题，思考档开到最顶，每次会话丢一块，输出那边的 token 要多花 20.1%。这些动作平时看着只是收拾桌面，代价按 token 结。

更别扭的是那道筛子认错人的时候。正常请求被拦下，账单照出，开发者这头活没干成钱也扣了，平台那边只多一条拦截记录。这件事避不开，只能提前算进预算里。

换个角度看，这套动作也说明模型公司怎么给自家的思考定价。同样的算力，能卖调用，也能卖训练材料，后者一旦流出去，替代品就在别人的机房里长大了。宁可少收当期那点过路费，也要把源头看住，这笔账他们算得很清。对下游的人来说，值得记住的是资产的位置变了，以前最贵的是模型本体，现在连对话记录都可能成为要谈条件的筹码。

落到日常工作上，还有几件小事值得提前安排。系统指令里不变的部分单独放，别让它跟着日期或用户标识一起变；长任务切成分段，每段收尾时把结论落到自己库里，而不是只留在会话里；用两家模型做编排时，接力那段要重跑一遍校验，别默认上一家的思考还能接着用。
