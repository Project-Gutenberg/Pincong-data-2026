### 知乎用户 平凡​ 发表
    
我从 Artificial Intelligence 把截至 8 月 3 日的数据下载了下来，它上面一共有 592 个模型。

![](https://images.weserv.nl/?url=https%3A//pica.zhimg.com/v2-7efe9015247b3a67361c2326aac72550_r.jpg%3Fsource%3D1def8aca)

价格便宜的模型使用起来不一定便宜
----------------

其中有 130 条数据同时具备正的 cost per task 和 intelligence index，能够放进对数坐标系中。为什么用这两个指标？其实很简单：

1\. Intelligence Index（智力指数）：

指的是模型的 “智商”，也就是它是否能够完成像高考数学题、写代码以及各种智力测试。

2\. [Cost per Task](https://zhida.zhihu.com/search?content_id=792547931&content_type=Answer&match_order=1&q=Cost+per+Task&zhida_source=entity)（单次任务成本）：

我觉得这是一个很妙的指标。它不是指单纯的 API 价格指标。如果只看 API 价格，有些模型因为本身很小，可能只要几 B、几十 B（参数），显得非常便宜；相比之下，几百 B 的大模型在这个指标上就会很吃亏。

但这个指标衡量的是完成一个任务所需要的 Token 量，这就尽可能避免了小模型因为参数量小而占便宜的优势。即使是参数量大的模型，如果你足够厉害，一步就能完成任务，那么你的 Cost per Task 就会非常低。

你看，这是它默认的 27 个模型，从最便宜到最贵。完成一个任务，像 DeepSeek-V4-Pro 是最便宜的，只要 0.05 刀；而对于 Claude Fable 5（也就是目前最贵的模型），它需要 3.15 刀。这里面差的可是六七十倍的差价。

![](https://images.weserv.nl/?url=https%3A//picx.zhimg.com/v2-b92cb3756c7125d657bd428ab9c28c85_r.jpg%3Fsource%3D1def8aca)

但你如果真的要单纯比较这个 API 的价格，那比它便宜的还真有的是，比如最近疯狂降价、大出名的 GPT 5.6 Luna，它的 API 价格甚至低于 0.01 刀。像那个小米的 MiMo-V2.5，也非常非常便宜。

![](https://images.weserv.nl/?url=https%3A//pica.zhimg.com/v2-1e9a06cf5a9c54a338f32840f60c2e13_r.jpg%3Fsource%3D1def8aca)

下面这个图就说明了 API 单价便宜，并不等于实际使用成本低。横轴是每百万 token 的 API 标价，纵轴是完成一项实际评测任务的平均成本。像 Ministral 3 这样的模型，单价看起来很低，但由于完成任务时消耗的输入、输出或推理 token 较多，最终成本反而明显高于整体趋势。相比之下，DeepSeek V4 Flash 不仅标价低，Cost per Task 也很低，说明它的优势不只是 “卖得便宜”，而是完成任务本身也更省钱。

![](https://images.weserv.nl/?url=https%3A//pica.zhimg.com/v2-d28ebcab6cf0d286af0844590d4f6112_r.jpg%3Fsource%3D1def8aca)

DeepSeek 的斩杀线到底杀掉了谁
-------------------

按照成本越低越好、分数越高越好的规则计算，这 130 个模型形成了 16 个帕累托最优点。DeepSeek V4 Flash 0731 的 Intelligence Index 是 49.9277，Cost per Task 是 0.0271308 美元，它正好站在前沿上。

GPT-5.6 Luna xhigh 的 Index 是 49.0677，Cost per Task 是 0.0316694 美元。换成 DeepSeek 以后，分数提高了约 0.86，成本还下降了约 14.3%，这就是一次标准的帕累托改善，Luna xhigh 也因此被 DeepSeek 严格支配。

但 GPT-5.6 Luna high 的情况不一样，它的 Index 是 46.0590，Cost per Task 只有 0.0215565 美元，比 DeepSeek 更便宜，只是分数低约 3.87。Luna max 的 Index 达到 51.2359，分数比 DeepSeek 高约 1.31，但任务成本也增加到 0.0473489 美元，约为 DeepSeek 的 1.75 倍，这两个模型都和 DeepSeek 各自保留了一项优势，不能互相支配，所以也都能留在前沿上。

DeepSeek 右下方那片区域，就是网上所说的斩杀区。凡是落进这个区域的模型，成本不低于 DeepSeek，Index 又不高于 DeepSeek，在当前两个指标下都可以被替换。

130 个可绘制点中，除去 DeepSeek 自己，有 91 个点被它支配。不过这里不能写成 91 个现役模型都被淘汰，因为 130 个点里只有 96 个没有被标记为 [deprecated](https://zhida.zhihu.com/search?content_id=792547931&content_type=Answer&match_order=1&q=deprecated&zhida_source=entity)，清理掉旧模型和弃用档位以后，DeepSeek 实际支配的现役模型是 64 个。

![](https://images.weserv.nl/?url=https%3A//picx.zhimg.com/v2-56d62302f0ae0eeafa41abf7910188a5_r.jpg%3Fsource%3D1def8aca)

红色的那部分区域，都是被斩杀的模型。因为你会发现，在帕累托最优点的所属公司寥寥无几，暂时看起来就只有四家：OpenAI、DeepSeek、[Groq](https://zhida.zhihu.com/search?content_id=792547931&content_type=Answer&match_order=1&q=Groq&zhida_source=entity) 以及 [Anthropic](https://zhida.zhihu.com/search?content_id=792547931&content_type=Answer&match_order=1&q=Anthropic&zhida_source=entity)。

这是很惨的一种现象。

这就跟我们经常看的玄幻小说里面一样：你在地界疯狂修炼，有朝一日终于成为了宗门里面的天才，再加上勤学苦练，终于习得了一身武功。结果准备飞升天界，飞上天之后，发现上面还有一群怪物在等着你。

这些红色点真不是什么默默无名的模型，其实都是有头有脸的公司做出来的，并且消耗了大量的财富才造出来。但就非常的无奈，它正好处在了这个尴尬的区域里面。

这张图里，横轴越往左越便宜，纵轴越往上能力越强，最理想的位置当然是左上角。可现实中的模型不会都挤在那里，能力提高往往需要更多推理和更高成本，于是图上形成了一条从左下向右上的边界，这就是[帕累托前沿](https://zhida.zhihu.com/search?content_id=792547931&content_type=Answer&match_order=1&q=%E5%B8%95%E7%B4%AF%E6%89%98%E5%89%8D%E6%B2%BF&zhida_source=entity)。

帕累托支配的判断并不复杂。假设模型 A 的成本不高于模型 B，Intelligence Index 又不低于 B，并且至少有一项严格更好，那么 A 就支配 B。既然换成 A 以后能力不会下降，成本也不会增加，B 在这两个指标下就没有继续保留的必要。

![](https://images.weserv.nl/?url=https%3A//pica.zhimg.com/v2-f91ed18083ea347b3c258bd02098a74a_r.jpg%3Fsource%3D1def8aca)

从 B 换到 A 的过程叫[帕累托改善](https://zhida.zhihu.com/search?content_id=792547931&content_type=Answer&match_order=2&q=%E5%B8%95%E7%B4%AF%E6%89%98%E6%94%B9%E5%96%84&zhida_source=entity)，也就是至少有一项变好，同时其他项目没有变差。如果一个模型找不到任何这样的替代者，它就是[帕累托最优](https://zhida.zhihu.com/search?content_id=792547931&content_type=Answer&match_order=3&q=%E5%B8%95%E7%B4%AF%E6%89%98%E6%9C%80%E4%BC%98&zhida_source=entity)。寻找全部非支配方案和整条边界的过程，通常叫[帕累托优化](https://zhida.zhihu.com/search?content_id=792547931&content_type=Answer&match_order=1&q=%E5%B8%95%E7%B4%AF%E6%89%98%E4%BC%98%E5%8C%96&zhida_source=entity)。

帕累托最优并不是综合冠军。前沿上有些模型非常便宜，但分数低一点，有些模型分数更高，同时也要多花很多钱。它们留在前沿上，是因为没有另一个模型能够不付出任何代价，把它们全面替换掉。

但我觉得现在的问题是，看起来 DeepSeek V4 的方案是处于这个 Pareto 最优，但实际上它是在我们目前的 benchmark 上面拿到了 100% 的分数。

我并不觉得现在的 100% 能够真正反映出跟人类齐平的智能，它更多的是一个还是挺主观的判别标准。如果以后到了 200 分是满分的情况下，那么这个 Pareto 最优就会有所改变。

当然，DeepSeek 肯定是非常牛逼的一个存在，但我们还是需要继续努力，去追求更高级、最高的智能，因为智能是没有上限的。同时，我觉得 DeepSeek 的策略目前看起来确实是最优的，那就是用尽可能少的 token，去达到尽可能高质量的智能。

### 一个公司要发新模型就会有参考标准

推理成本是所有人实打实会感受到的东西，而这样的降维打击，更是直接打击了稀缺性叙事。

如果说训练大模型是画了一张未来的饼，那么推理大模型就是饼的商业变现方式。

如果推理端的 token 供应都无法维持高价，那么市场更没有耐心为大模型的军备竞赛持续输血。

* * *

**挤干水分**

大模型的训练端和推理端的成本存在很大差异。

推理端更偏工业，模式跟过去的 IT 产业没有区别。

成本更多就是算力的采购成本，使用成本和软件开发成本，总体上是相对确定的，标准化的，营收和毛利也是清晰的，普通人也能评价好坏。

训练端则不是这样，训练端更偏科研，难度非线性，价值不直观，存在大量试错和资源空转。

因此大多数人无法直观评价好坏，这就意味着其中有很多水分，滤镜没被打破之前，还能卖出价值；滤镜一旦被打破，就会价值回归，俗话说**退潮之后才知道谁在裸泳**。

* * *

**DeepSeek 是如何斩杀的**

DeepSeek 通过低成本训练，用远低于头部的成本，训练出水平接近的大模型，限制了上限，把 “**用最多的钱训练出最牛的模型然后賺垄断的钱**” 这个故事干碎了。

再通过模型开源以及低成本推理，构建行业竞争力，同时限制了模型研发成本转嫁给推理消费者的行为，让大多数模型厂商只能賺钢镚的钱，不允许超额利润。

通过这两板斧，砍掉 OpenAI 们的头和脚，要么低价竞争，要么就只能成为泡沫下的牺牲品。

* * *

其实” 斩杀线”，不止是” 单价” 这一层，便宜、真便宜、便宜到友商难受，其实在真实的生产环境里，决定一个模型生死的，不是标价，而是 [Cost per accepted task](https://zhida.zhihu.com/search?content_id=792511412&content_type=Answer&match_order=1&q=Cost+per+accepted+task&zhida_source=entity) ，每一次被人真正采纳的产出，到底花了多少钱。

举个我们自己踩过的坑。有一阵子我们贪便宜，把一段跨多文件的自动重构任务从旗舰模型切到了低价模型。单看标价，省了将近九成。结果呢？这类开放式的 Agentic 任务有个要命的特性：决策错误空间极大，只要在多轮循环的前几步走错一步，错误会指数级累积放大。模型吭哧吭哧跑了小半小时，烧掉将近几千万 token，最后交出来的东西还是废的，人工又得从头返工。

单次触发是便宜，但重试三四次、再加上工具调用格式出错要修、再加上最后人工审核的工时，综合成本未必比那个” 贵但一次过” 的旗舰低，甚至可能更高。省下来的 API 费，全填进了工程师的返工时间里。

所以在工程级别，还需要关注：

*   **幻觉率**。第三方测的 AA-Omniscience 指标里，V4 Flash 0731 的幻觉率是 84%，准确率 37%。作为对比，旗舰级的 [Claude Sonnet 5](https://zhida.zhihu.com/search?content_id=792511412&content_type=Answer&match_order=1&q=Claude+Sonnet+5&zhida_source=entity) 幻觉率大概压在 37% 左右。
*   **吐字太长**。它的 Verbosity 是满级 4/4，跑一套评测能吐两亿多输出 token。输出越长，暴露幻觉的面越大，账单也越厚。
*   **工具调用的格式毛刺**。给可选字段乱塞 `null`、把 JSON 数组输出成转义字符串、把文件路径写成 Markdown 自动链接…… 这些在 Agent 流水线里都是能直接把流程打断的坑。想用好，你得自己搭一层 `Tool-calling repair layer` 去兜底，这层工程成本，也是钱。

” 斩杀线” 是一个消费者视角的概念，描述的是” 同样的钱能买到什么”；但落地是一个生产者视角，需要关注的是” 同样一件事要花多少钱”。

所以 [V4 Flash](https://zhida.zhihu.com/search?content_id=792559867&content_type=Answer&match_order=1&q=V4+Flash&zhida_source=entity) 划出来的这条线, 含义不是 "梁文锋想卖多少钱", 而是 "这个性能, 按机器成本跑, 就值这个钱"。它谈不拢, 也收购不掉, 你把公司买下来, 散出去的权重文件也收不回去。这才是[闭源公司](https://zhida.zhihu.com/search?content_id=792559867&content_type=Answer&match_order=1&q=%E9%97%AD%E6%BA%90%E5%85%AC%E5%8F%B8&zhida_source=entity)真正难受的地方。

同一个高赞还有个判断, 说只要梁文锋活着, 友商就拿不到现金流、融不到资, 最后归零。这话我觉得只对了一半。

散点图能斩杀的, 只有**卖接口调用**这一种生意。你看头部几家收钱的路子, 都在往订阅、席位、企业合同上挪, 这些收入根本不从那张图上过。OpenAI 7 月 30 号把 [GPT-5.6 Luna](https://zhida.zhihu.com/search?content_id=792559867&content_type=Answer&match_order=1&q=GPT-5.6+Luna&zhida_source=entity) 砍价 80%, 输入价从每百万词元 (token)1 美元降到 0.2 美元, 这个动作与其说是应战, 不如说是表态: 调用差价这块毛利我不要了, 我守的是入口。守得住入口的公司, 被斩进图的右下角, 顶多难看, 不致命。

真正会死的是中间那层: 模型没到最强, 手里又没有入口, 收入全靠调用差价。对这类公司, 那张图就是判决书, 因为卖调用这门生意没有忠诚度可言, 换模型就是改一个接口地址的事。我自己挂的几条个人自动化流程就是这么换的, 哪个够用又便宜切哪个, 切的时候没有任何心理活动。有个模型聚合平台叫 [OpenRouter](https://zhida.zhihu.com/search?content_id=792559867&content_type=Answer&match_order=1&q=OpenRouter&zhida_source=entity),7 月初有媒体统计过, 上面美国企业的调用量里, 跑在中国模型上的比例, 按周统计的峰值一度到过 46%。企业嘴上讲合规讲安全, 手上比谁都诚实。

所以 "斩杀线" 更准确的名字, 可能是**商业模式筛选线**: 它筛掉的不是性能不够的模型, 是 "性能不顶尖、又只会卖调用" 的公司。能留在场上的只剩两种, 一种往上顶, 把最强那一口的差距拉开, 继续收溢价; 一种往入口退, 退到用户感知不到底下跑的是哪家模型的位置。

这条线最吓人的地方也在这: 它只往左上方挪, 挪的节奏不由任何一家公司决定。这次是 DeepSeek 推的, 下次可能是别家的开源旗舰。对闭源公司来说, 这等于在跟 "开源" 这个不需要赚钱的对手长跑。

先说结论：DeepSeek 的 “斩杀线”，不是宣布谁已经成为大模型冠军，而是逼所有模型回答一个很现实的问题：

你凭什么比它贵？

很多人把这件事理解成一次模型能力排名，仿佛只要在榜单上超过 DeepSeek，就能躲过这条线。其实不是。它真正改变的，是大家评估模型的坐标系：以前我们问 “谁最强”，现在还要追问 “多花的钱，究竟换来了什么”。

\## 一、斩杀线首先是一条采购线

企业采购模型，最终买的不是一个漂亮的分数，而是一项能稳定交付的能力。

模型的价格当然重要，但价格从来不是账单上的那个数字这么简单。一个模型看起来便宜，如果经常答错、需要反复重试，或者输出格式不稳定，接入它之后还要增加人工审核、规则兜底和故障排查，那么它的真实成本就会被重新计算。

反过来，一个更贵的模型，如果能少走几轮流程，减少返工，让结果更容易直接进入业务环节，它就可能是更便宜的选择。

所以所谓 “斩杀”，并不是 “比 DeepSeek 弱的模型全部消失”，而是：一个模型如果既没有明显更强的能力，又无法解释自己的价格溢价，采购者就会自然地把它放进替代清单。

这是一条问责线。

它要求每一个更贵的模型说明白：你的溢价，是来自更高的成功率，更低的延迟，更稳的工具调用，还是某个别人替代不了的专业能力？

\## 二、真正该比较的是成功任务成本

只看 Token 单价，很容易得到一个过于乐观的结论。

开发者实际要完成的，通常不是 “让模型输出一段文字”，而是让它完成一个任务：读懂上下文，调用工具，修改文件，处理异常，给出可以被人接受的结果。

中间任何一步出错，前面省下的调用费用都可能被重新试一次的成本吃掉。

因此，更有意义的指标应该是：

\> 完成一个最终被采纳的任务，平均要花多少钱？

这个数字至少包含四部分：模型调用费、重试和上下文消耗、工具调用失败造成的额外成本，以及人工核验和返工的时间。

这也是为什么同一个模型，在聊天演示里表现很好，放进真实工作流后却未必同样划算。演示只展示一次成功的答案，生产环境要承担的是连续运行、异常分支和失败恢复。

DeepSeek 的压力并不只来自它 “便宜”，而是来自它把“够用的能力” 与较低的使用门槛放在了一起。对于大量有明确规则、可以自动验证的任务，这个组合尤其有吸引力：代码格式可以检查，结构化输出可以校验，简单的流程错误也可以被程序拦住。

但这不等于所有场景都应该无条件切换。需要长链路推理、复杂判断、极高稳定性，或者失败代价特别高的任务，仍然要看模型的实际成功率和兜底成本。

\## 三、它抬高了中间档模型的生存难度

大模型市场最尴尬的位置，往往不是顶端，也不是底端，而是中间。

顶级模型可以卖能力上限，告诉客户：在关键任务上，我能提供更高的确定性。轻量模型可以卖效率，告诉客户：只要任务边界清楚，我能以很低的成本批量完成。

真正困难的是那些既没有旗舰级能力，又没有明显价格优势的产品。过去，用户可能会因为品牌、习惯或 “总归比小模型强” 而选择它们。现在，DeepSeek 提供了一个很直观的参照物：如果你比它贵，至少要比它强；如果你没有强很多，就应该便宜；如果既不够强也不够便宜，那还剩下什么？

这就是 “斩杀线” 最锋利的地方。

它斩掉的不是某一个公司的名字，而是一种模糊的产品定位。模型不能只说 “我也能做”，还要说清楚 “我为什么值得被优先选择”。

\## 四、这不是一条永远不变的线

不过，把 DeepSeek 说成永远的终点，同样是不准确的。

模型能力会更新，价格会变化，用户任务也会变化。某个模型今天在通用代码任务上很有优势，明天可能被新的版本追上；某个模型的公开价格很低，但如果[缓存命中率](https://zhida.zhihu.com/search?content_id=792626830&content_type=Answer&match_order=1&q=%E7%BC%93%E5%AD%98%E5%91%BD%E4%B8%AD%E7%8E%87&zhida_source=entity)、服务稳定性或并发能力不适合你的业务，实际账单和体验也会完全不同。

DeepSeek 官方更新页已经说明，2026 年 7 月底发布的 [DeepSeek-V4-Flash-0731](https://zhida.zhihu.com/search?content_id=792626830&content_type=Answer&match_order=1&q=DeepSeek-V4-Flash-0731&zhida_source=entity) 主要是后训练更新，API 模型名为 \`deepseek-v4-flash\`；这次更新的是 V4-Flash API，V4-Pro API 与 App/Web 模型并没有同步变化。这个信息本身就提醒我们：讨论 “DeepSeek” 时，必须说清楚具体版本、具体入口和具体任务，不能把不同产品混成一个抽象的神话。

所以，斩杀线不是一条刻在石头上的性能线，而是一条动态的选择线。它随着价格、能力、延迟、稳定性和任务要求一起移动。

\## 最后

DeepSeek 不需要在每一张榜单上都拿第一。

只要它足够便宜、足够能用，就会让所有比它贵的模型先解释自己的溢价。这个问题一旦成为行业共识，模型厂商的竞争就不再只是 “我能不能把分数再提高一点”，而是 “我能不能让用户愿意为这部分提高付钱”。

对于普通开发者来说，选模型也不该只看榜单和 Token 单价。把自己的真实任务拿出来，记录成功率、重试次数、延迟、工具调用稳定性和人工返工时间，再算每个最终交付结果的成本。

所谓 “斩杀线”，斩掉的不是所有竞争者，而是那些说不清自己为什么值得更贵的产品。
