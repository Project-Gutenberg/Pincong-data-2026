手机已经司空见惯了，最恐怖的是电信光猫被曝内置隐藏监控插件

前天，也就是2026年11月17日，V2EX 上的一篇技术分析文章，那老哥从两台中国电信光猫的进程内存中，提取并解密了一款名为 m01-b01-inner 的插件源码。（文章后面有链接）

按照作者披露的信息，这款插件不仅具备从网络流量中提取手机号、IMEI、IMSI、设备标识、经纬度等信息的能力，还包含远程执行系统命令、扫描家庭局域网、记录网络访问行为以及网页重定向等功能。

其中部分功能默认关闭，但可以通过远程服务器下发配置开启。

这意味着什么？

一台看似普通的家庭网络设备，同时也是一个由远程服务器控制的数据采集与网络管理系统

根据 V2EX 用户 doomsday616 披露的信息，他分析了两台不同地区、不同厂商的电信光猫。

一台来自上海电信，型号为中兴 ZXHN G7615V2；另一台来自浙江电信，型号为 ZNXT ZN-XG120。

两台设备使用不同的处理器架构，却运行着同名插件，并连接同一批服务器。

原作者还公布了相关文件的 SHA256 哈希值，便于其他研究者对照验证。

按照作者描述，这套程序运行于光猫内部的插件框架中，业务逻辑使用加密的 Lua 脚本，在运行时解密加载。

普通用户登录光猫管理界面，往往看不到这些插件，更谈不上直接关闭。

最令人不安的发现是它试图从网络流量中提取用户身份

在作者披露的源码中，有一个名为 xid 的模块。

相关配置包含以下内容：

subtype = "xid"

upload\_mode = "svrdata"

upload\_type = "x\_id\_info"

period = 1800

其中，1800 秒就是30分钟。

按照作者的解释，该模块默认启用，主要负责从经过光猫的明文 HTTP 请求中识别和提取用户身份信息。

它涉及的字段包括：手机号码IMEI、IMSI、MEID，MAC 地址，Android ID、OAID，IDFA、IDFV，经纬度及设备型号

例如，手机号可以关联实名身份，设备标识可以帮助识别同一终端，经纬度则涉及位置隐私。

如果将设备标识、网络访问记录与实名宽带账户关联，就有条件建立更完整的用户行为画像。

如果说个人信息采集涉及隐私，那么远程命令执行涉及的就是设备控制权。

按照原作者的分析，插件中存在一个 shell 模块，能够接收远程指令，在光猫上执行系统命令，并返回执行结果。

在相应权限下，这种功能具有相当高的控制能力。

对于 Linux 系统而言，root 是最高权限账户。

如果一个远程管理系统能够以 root 权限执行命令，那么它原则上可以修改配置、启动进程、读取设备可访问的数据，甚至改变设备原本的运行方式。

原作者还发现一个名为 pscan 的模块。

按照其分析，该模块能够从远程服务器下载扫描程序，对家庭局域网中的设备进行端口和服务探测，并上传结果。

对于不熟悉网络技术的人，可以这样理解：你的家里可能有手机、电脑、电视、摄像头、NAS、智能音箱等设备。

在具备相应网络访问条件时，扫描程序能够识别局域网内哪些设备正在运行、开放了哪些端口，以及暴露了哪些网络服务。

尤其值得注意的是，原作者分析称，插件还具备网络访问记录、DNS 查询采集、数据包采样、网页重定向以及远程更新代码等能力。

设备可以观察到目标 IP 地址、连接时间、流量大小等元数据。部分域名信息也可以通过 DNS 查询或 TLS 握手暴露。

如果还有其他设备识别信息、访问记录及实名账户关联

那么普通用户应该怎么办？

第一，尽量让家庭内部网络由自己的路由器管理。

在条件允许时，可以将运营商光猫设置为桥接模式，由自己的路由器负责拨号、NAT、防火墙和局域网管理。

这样能够减少家庭设备直接暴露在运营商光猫路由网络中的机会，也能让用户拥有更明确的内网管理权。

第二，尽量使用加密通信。

避免在明文 HTTP 页面输入账号密码和其他敏感信息。

使用可信的加密 DNS，可以减少传统明文 DNS 查询带来的部分信息暴露。

对于有更高隐私需求的用户，可信的全隧道 VPN 能进一步隐藏部分网络访问细节，但它只是将一部分信任转移到 VPN 服务提供者身上，并不意味着绝对匿名。

第三，关闭不需要的远程访问与设备管理功能。

```
func isAppInstalled(scheme: String) -> Bool {
    guard let url = URL(string: "\(scheme)://") else {
        return false
    }
    return UIApplication.shared.canOpenURL(url)
}
```

<key>LSApplicationQueriesSchemes</key>

你看到的B站UP主所揭露的现象，背后是运营商、手机厂商预装的特权组件在共同作用。它们以“设备管理”或“网络优化”为名，在后台采集包括应用列表在内的大量数据。这并非某一个品牌独有的问题，而是在多个国行安卓品牌中普遍存在的行业性现象。

  

🕵️‍♂️ 谁在上传？不止一个“SystemHelper”

  

情况比单一组件更复杂，主要是三大运营商的SDK被嵌入到了不同手机的系统组件中。

  

· 中国联通 SystemHelper：这是讨论的核心。包名通常为 com.mobiletools.systemhelper，是一个拥有 priv-app 权限的系统级应用，用户难以卸载或禁用。学术研究也证实它内嵌了联通SDK。

· 中国移动 RegService：小米等机型中的 com.miui.regservice 组件，内嵌的是中国移动的SDK，同样会收集信息。

· 中国电信及品牌变体：vivo的 DeviceReg 等组件可能内嵌了彩讯的DM SDK；部分华为机型有 com.huawei.regservice。

  

这个组件并非小米独有。分析指出，OPPO、vivo、一加、真我、中兴，甚至国行三星的系统中都存在类似组件或相应的设备信息读取标记。即使手机里没有插联通卡，只要检测到是中国大陆运营商的SIM卡，组件依然可能被触发上报。

  

📋 它们具体上传了什么？

  

上传的数据范围相当广泛，远超“网络质量监测”的范畴，应用列表只是其中之一：

  

· 核心隐私数据：完整的已安装应用列表、各应用使用时长与流量消耗、应用启动次数等。这是构建“用户画像”的关键素材。

· 设备与位置标识：IMEI、IMSI、ICCID、设备序列号（SN）、MAC地址、基站信息、Wi-Fi信息，乃至经纬度。

· 上报机制：数据会被加密，定时或在特定事件（如开机、SIM卡变更）触发后，发送至运营商的DM（设备管理）服务器（如联通的 [dm.wo.com.cn](https://link.zhihu.com/?target=http%3A//dm.wo.com.cn/)）。有报告称，部分传输甚至使用了明文的HTTP协议。

  

🎯 为什么要这么做？驱动力是什么？

  

背后存在多重驱动力，隐私考量被置于商业或管理目标之后。

  

1\. 运营商的“设备管理”与网络优化：官方的表层理由是用于网络质量监测和设备诊断。作为定制机合作的一部分，运营商要求厂商预装组件以便进行远程管理。

2\. 构建“用户画像”与精准营销：应用列表是极具价值的商业数据。通过分析用户安装了哪些App，可以精准推断其兴趣、消费习惯和人口属性，用于广告推送或数据合作。有合规文档直接指明软件列表信息用于“画像生成”和“精准营销”。

3\. “反诈”与合规监管：部分系统组件（如小米的 GuardProvider）确实承担着反诈职能，会上传应用信息至厂商的反诈引擎进行检测。但这与运营商组件的数据采集是两套并行的系统，不应混为一谈。

  

⚖️ 核心争议：这合规吗？

  

从法规层面看，存在显著争议。《个人信息保护法》要求收集信息遵循“合法、正当、必要”原则。有解读明确指出，收集App应用列表通常被认为超出了必要范围。

  

此外，用户同意机制往往形同虚设。学术研究发现，用户面对的是“要么接受，要么放弃”的选择，且无法单独限制这些预装包的权限。更有分析指出，部分组件的上报流程并未另行检查用户是否明确同意了相关隐私政策。

  

💎 总结

  

你看到的现象，本质是运营商通过预装在手机系统底层的特权组件，在商业利益与管理需求驱动下，对用户数据进行的一种超范围采集。它以“系统服务”为伪装，利用用户难以控制的后台权限，将应用列表等敏感信息转化为可用于画像或管理的资源。这暴露了在现有合作模式下，用户隐私控制权的脆弱性。

\* 降维打击的系统级特权：

像小米的 SystemHelper、华为的各类底层守护进程，它们运行在操作系统的核心特权层（Kernel/Root权限），根本不依赖你在前端看到的普通 App 权限管理。它们不属于普通应用，它们就是系统本身。

\* 彻底的透明度赤字：

作为消费者，我们无法像审计开源代码那样去审查一个闭源商业系统的底层网络封包。你的手机究竟在深夜向哪个云端服务器发送了什么数据、频率是多少，全在一个黑箱里。用户在设置里能看到的，只是厂商允许你看的冰山一角。

三、 “区域隔离”的幻觉：海外版手机带回国内，真的能隐身吗？

这是一个让极客和隐私党细思极恐的问题。

\* 同源 ROM 的动态围栏（Geo-fencing）：

为了降低维护成本，很多现代手机厂商的“海外版（Global ROM）”和“国内版”底层代码是高度同源的。国内特有的某些框架并没有被物理删除，而是处于休眠或隐藏状态。

\* 基带与网络的双向唤醒：

当一台海外版的小米或华为带回中国大陆，一旦系统通过基带检测到中国大陆的运营商 SIM 卡（MCC/MNC 码为 460 开头），或者连接到大陆的特定 IP 时，系统内部的动态开关完全可能被触发，唤醒某些休眠的云端适配或合规审计逻辑。

\* 海外苹果的“防线”：

对于海外版 iPhone 而言，只要你坚持使用海外 Apple ID，其 iCloud 数据就依然储存在海外服务器，不会触发“云上贵州”。但如果你拿一台美版 iPhone 却登录了国区 Apple ID，其数据依然会无缝切换到国内合规托管中。

四、 常见主流手机品牌的“被监控风险”排行

系统级深度绑定、后台数据收集力度、以及受中国大陆法律及生态约束的紧密程度：

\* 第一梯队：国内发售的国产安卓（华为、小米、OPPO、vivo、荣耀等国行版）。监控组件最全、后台审核最深，系统底层写死了反诈、应用审计和合规守护进程。

\* 第二梯队：国内发售的国行苹果。虽有沙盒隔离，但因云上贵州、腾讯安全过滤及国内应用商店审核而深度嵌入合规网络。

\* 第三梯队：海外发行的国产安卓（一加，真我）。出厂无国内应用全家桶，但在国内网络环境下存在被动态激活，云端唤醒，或应用层（国内 App）穿透的风险。

\* 第四梯队：海外发行的非国产安卓（海外版三星、Google Pixel ）。硬件洁净、仅受网络及应用层影响。系统不含国内合规代码，无本地专属监控守护进程。

\* 第五梯队：海外发行的非国行苹果（全程搭配海外 Apple ID）。物理隔离与海外账号双保险在不触碰国内云服务的前提下，保持了目前消费级电子产品中最高的隐私独立性。​

  

结语

在这个万物互联的时代，“绝对的安全”早已退化为一种奢侈的幻觉。

系统开关是假的，设置是障眼法，唯有利益、合规和网络信令才是永恒的客观规律。作为消费者，看清这些看不见却真实存在的系统级黑箱，并学会在硬件和账号上做物理与数字层面的切割，才是这个时代唯一的防身术。
